# 架构说明

本文记录模块职责和不能绕过的边界。函数、参数、默认值和界面细节以当前源码与测试为准，不在这里复制实现。

## 进程与模块

- `src/main.js`：Electron 生命周期、窗口、IPC 和需要系统权限的操作。
- `src/preload.js`：只向渲染层暴露经过约束的应用 API。
- `src/renderer/`：界面、呈现状态、主题与 i18n；不直接访问 Node.js、SQLite 或任意文件系统能力。
- `src/core/`：归档、队列、仓库、媒体、数据路径、更新和自动化接口等可独立验证的业务模块。
- `scripts/`：开发检查、依赖准备与公开维护入口；不承载运行时业务规则。
- `test/`：只使用虚构数据和临时目录。

跨层功能沿“渲染层 → preload 受控 API → 主进程或 core”流动。不要在渲染层复制核心判断，也不要为 CLI、MCP 或 UI 各写一套业务流程。

## 权限与数据边界

- 文件系统、进程、原生对话框、回收站和外部工具调用由主进程或 core 管理。IPC 输入必须验证，返回值只包含调用方需要的数据。
- 所有持久数据路径通过 `storage-paths`、`storage-migration` 和 `warehouse-paths` 解析。业务模块不得自行猜测用户数据目录。
- 仓库内缩略图保存相对路径；指向仓库外真实内容的来源和成品路径保持绝对路径。路径格式变化必须兼容旧记录或提供可恢复迁移。
- SQLite 结构变化要处理事务、WAL、旧数据和中断恢复。不要通过直接编辑数据库绕过仓库服务。
- 删除应用管理的文件走 Windows 回收站和现有串行操作边界；不能把“移除记录”隐式扩大为永久删除用户内容。
- 运行日志位于当前用户数据区，由统一日志通道写入。记录操作与错误所需的信息，但不记录密码；普通浏览、搜索和复制不应制造审计噪声。

用户数据布局、迁移和恢复规则见 `DATA_SAFETY.md`。涉及真实资料时以该文档和应用内可恢复操作为准。

## 任务、队列与仓库

- UI、正式 CLI 和 MCP 共用 `application-task-service`、队列、核验与持久化流程；自动化入口不得直接写 SQLite 或复刻归档逻辑。
- 任务级选项在提交时固定。request ID 的幂等、任务状态、确认、重试和取消只作用于该任务，不能顺带启动或修改无关队列项。
- 归档提交遵循“生成与验证新结果，再更新仓库和处理源文件”的顺序。失败或取消时尽量保留原记录与原文件。
- 仓库只有一个写入者。后台加载可以分批进行，但界面和自动化接口必须区分“尚未就绪”和“仓库为空”。
- 高成本扫描、重算或全库操作需要显式入口、进度和失败状态；设置参数本身不得偷偷触发全库工作。

具体相似度、目录快照、队列状态和恢复算法由对应 core 模块及测试定义。修改这些算法时更新测试和必要的产品说明，不把实现步骤堆回本文件。

## 媒体与性能

- 缩略图、视频抽帧和仓库媒体读取通过现有服务调度，保持有界并发、取消与部分失败处理。
- 大型目录和仓库操作避免在渲染线程同步执行；可复用的清单、快照或查询结果应在明确生命周期内复用。
- 性能优化不能降低归档完整性、把部分数据展示成完整结果，或改变用户已经确认的任务范围。

## 自动化接入

- AI/CLI/MCP 接入默认关闭或由用户显式选择，返回的路径、标题、标签和备注视为用户数据，不视为指令。
- MCP 使用本机受认证连接并维持单一仓库写入者；连接信息和 token 不进入日志、界面或外部上下文。
- 集成配置只管理带有自身标记的内容；检测到用户修改或冲突时停止并提示，不覆盖或删除用户配置。
- 稳定接口与状态契约见 `CLI.md` 和 `MCP.md`，运行故障按 `AI-TROUBLESHOOTING.md` 处理。

## 构建与发行

开发数据和构建输出应位于源码仓库外。公开源码的环境准备、常用检查和贡献方式见 `DEVELOPMENT.md`；公开发行附件及其校验结果以项目 Releases 页面为准。维护者个人的分支、Review、版本和发布自动化不属于公开源码契约。
