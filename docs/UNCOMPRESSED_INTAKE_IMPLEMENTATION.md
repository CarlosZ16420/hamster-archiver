# 不压缩入库实施记录

本轮按方案 v1.2 完善未压缩目录的续办能力，保留 4.6.15 版本号，仅更新私有源码与本地 Current。没有公开发布或长期同步服务。

## 实施映射

| 工作包 | 实施位置与行为 |
| --- | --- |
| P1 快照／差异 | `manifest.js`：版本化文件、目录、完整性、错误快照；基于路径、大小、精确修改时间的 O(n) 差异，不为报告读取内容哈希 |
| P2 临时计划 | `store.js`：pending manifest 使用版本 2 对象，保存数组之外的目录、错误和快照；兼容旧数组 |
| P3 来源路由 | `queue-manager.js`、`scanner.js`：直接添加与父目录候选均先查同源元数据索引；命中未压缩目录时不递归统计、不被小项目过滤阻断 |
| P4 批次／查重 | 明确 `taskKind` 与 `duplicatePolicy`；更新批次固定 ID，确认、模式选择及定时恢复保留范围；覆盖续办禁用自动跳过，独立新建仅排除已确认的同源记录 |
| P5 库内压缩 | 排队只做根检查，执行时取得当前快照并更新统计；压缩前任意目录变化须确认；本次快照直接传给现有归档引擎 |
| P6 增量预览 | `thumbnail-service.js`：稳定保留有效旧预览并计入上限，仅生成新增、修改或缓存失效的必要预览；新缓存使用当前任务目录，旧缓存所有权随记录保留 |
| P7 界面／位置 | 详情与批量更新入口、中英文报告、200 项分页、同源元数据展开、可关闭的说明；重设位置只检查根类型，不自动重建目录 |
| P8 提交／恢复 | 同 ID 原子替换、保留最新人工字段；失败补偿沿用原机制；已提交结果按 `archiveJobId` 恢复，不重复归档；失效自动封面解除关联并提示 |
| P9 风险验证 | 单元与临时目录生命周期检查涵盖增量复用、旧数据、固定批次、确认失效、空目录、单视频、恢复和自动化回执 |

## 行为边界

- 更新仅新增时自动合并；有删改或历史信息不足时等待三选一。转压缩有任何变化，包括仅新增，也先确认。
- 默认同源目标按 `sourceSnapshotUpdatedAt`，兼容回退内容提交时间，不按标题、标签等元数据编辑时间。
- 无变化更新仅保存检查时间，不改清单、源快照或内容索引，不重建媒体。
- 等待用户确认后重新枚举一次；确认快照未变化则传递复核结果继续处理，已变化则旧决定失效。
- 正常连续准备阶段只枚举一次；既有压缩后复核与最终原文件后处理前复核仍是独立安全检查，现在可发现新增文件和空目录。
- 目录更新永远保留原文件；转压缩成功后按原设置移动、回收或保留，不强制改为保留。
- 单视频不进入目录差异报告；MD5 一致按既有开关自动跳过或人工确认，极小文件目录采样规则不屏蔽单视频 MD5。
- AI／CLI 复用同一路由；目录变化返回 `needs_confirmation`、快照与目标引用，`continue` 不代表覆盖授权。使用桌面完成三选一，或显式跳过。
- 位置修复阻止已有活跃绑定任务，失败回滚路径字段和索引；更换位置不代表内容已确认相同。

## Review 与实际验证

完整差异 Review 点名修复了以下风险：未绑定批次的确认误启动无关任务、过期临时清单覆盖当前扫描、压缩校验遗漏新增文件、指纹失败丢掉文件事实、重复提交恢复、路径修改落盘失败、单视频元数据跳过及自动化确认状态遗漏。

开发检查按这些风险点执行，不属于正式发行 QA，也不是 Current 构建的隐式步骤：

- JavaScript 语法与差异空白检查。
- 快照、队列、归档、SQLite 持久化、中英文与预览相关检查。
- AI／CLI 任务契约、MCP 与父目录扫描相关检查。
- 临时数据均位于系统 temp，和开发及生产资料隔离；未操作真实用户内容。

此前全套检查曾暴露旧 `ui-state` 对中央列定义迁移前字面量的断言，以及并行媒体超时计时波动。前者不属于本轮功能修改，后者单独检查通过；不能将此前全套结果称为全部通过。

没有执行 Current 烟雾测试或自动启动；Current 是人工体验入口。尚未测量方案的大规模真实硬件矩阵（1 千／1 万／10 万文件、机械盘、外接盘），不提供未经实测的耗时或性能提升百分比。公开发布前应按正式 QA 流程安排 Windows 交互与硬件性能验收。
