# UI 开发指南

本文件只描述稳定的界面边界，不冻结像素、控件顺序或某次功能迭代的验收细节。当前结构和行为以 `src/renderer/index.html`、`app.js`、`styles.css`、`i18n.js` 及相关测试为准。

## 信息架构

- 顶层保留“仓库”和“归档工作台”两个入口，默认进入仓库。
- 工作台由收纳设置、扫描与队列、运行日志组成；仓库由概览、筛选与视图工具、结果区和详情组成。
- 新功能优先进入现有页面、设置组、工具栏、对话框和队列，不为同一状态再建一套容器、标题或操作入口。
- 设置、队列、仓库记录和任务状态必须各自保持单一事实来源；渲染函数重复执行不得重复绑定事件。

调整信息架构时，以减少重复和保持主流程清晰为目标。现有布局是起点，不是禁止合理重构的历史模板。

## 交互与状态

- 长时间、高成本或可能改变数据的操作必须由用户明确触发，并显示范围、当前状态、结果以及可用的取消或恢复方式。
- 危险操作说明对象、影响和恢复路径；默认焦点或回车操作不得指向不可逆动作。
- 加载、空数据、失败、暂停、等待确认和部分完成是不同状态，不能互相冒充。依赖完整仓库数据的操作必须等待加载完成。
- 响应式布局应保持主要操作可达、文字可读、表格和工具不遮挡；只有内容确实放不下时才滚动或换行。
- 图片和视频按需加载并限制并发。不能用 DOM 的 `loading=lazy` 代替对 IPC 或文件读取的调度。
- 选择、分页、筛选和详情之间的状态应可预期；新增手势时兼顾鼠标、键盘、焦点取消和内容重绘。

具体业务规则（归档、重复判断、目录更新、删除恢复等）属于产品或核心模块，不在 UI 文档重复描述。

## i18n 与用户数据

- 所有用户可见的静态和运行时文案都提供中文与英文；不要在业务分支散落只覆盖一种语言的文本。
- 当前渲染层以中文为源文本，通过 `i18n.js` 翻译。新增文案应沿用现有通道，除非任务明确包含 i18n 架构迁移。
- 标题、标签、备注、路径、用户输入和系统原始错误属于用户数据，默认保持原文。动态模板只翻译已知界面片段。
- Electron 原生对话框不经过 DOM 翻译，必须根据当前语言显式提供标题、正文和按钮。
- 切换语言只改变呈现，不重建用户数据、不改变任务或选择状态。新增动态文案时检查切换后的即时刷新。

## 可访问性与视觉系统

- 优先使用原生语义元素；图标按钮、输入、菜单、对话框和自定义交互必须有可访问名称、明确焦点和键盘路径。
- 对话框打开后管理焦点，关闭后返回触发位置；Esc 和关闭按钮行为保持一致。状态提示使用合适的 live region。
- 不能只靠颜色表达选择、错误或进度。正文、次要文字、状态色和交互控件保持足够对比度，并支持 `prefers-reduced-motion`。
- 主题只覆盖语义颜色与效果变量，不复制页面结构。新增或改名主题时覆盖现有变量、设置正确的 `color-scheme`，并迁移旧偏好值。
- 视觉数值应复用现有 token 和组件规则。只有确有共享价值时才新增 token，避免把一次对齐结果写成永久规范。

## 修改后的最小检查

根据改动范围选择相关检查，不要求每次机械执行全部项目：

1. 中文和英文的正常、空、加载与错误状态。
2. 常用桌面宽度与窄窗口下的溢出、滚动、工具可达性和详情定位。
3. 键盘操作、焦点返回、可访问名称和减少动态效果。
4. 事件是否只绑定一次，异步结果是否会覆盖更新后的状态。
5. 主题变量、浅色/深色原生控件及关键文字/状态对比度。
6. 截图、日志和错误提示不包含真实用户资料、密码或不必要的绝对路径。

行为已有自动测试时优先更新测试；纯视觉变化采用有针对性的人工对照。不要为文档中的措辞或像素值编写脆弱断言。
