# UI 与 i18n 约束

当前 4.5.x UI 信息架构是后续修改的基线：工作台、队列、仓库和设置各自只保留一个主容器与一个主标题。历史原型位于 `docs/prototypes/new-ui/`，只用于参考，不能作为运行入口。

## 修改原则

- 先复用已有卡片、字段和对话框，不嵌套重复的功能框或标题。
- 用户可见文案必须通过 i18n 键提供中英文，不在业务逻辑中散落硬编码文本。
- 队列阶段、预计时间和日志属于运行时文案，必须使用阶段文本翻译通道；由多个片段组成的内容按 ` · ` 分段匹配，不能只依赖整句静态词典。
- Electron 原生对话框不经过渲染层 i18n，必须根据当前语言显式提供中英文按钮、标题、说明和错误消息。
- 中英文切换不重建用户数据，不改变任务状态。
- 控件只绑定一次事件；渲染函数重复执行不能叠加监听器。
- 需要长时间运行的操作必须由用户显式触发，并展示范围、进度和取消/失败状态。
- 修改相似度强度只保存后续计算参数，不自动全库重算；单项或全库重算使用独立动作。
- 危险动作说明对象、影响和恢复方式，默认按钮不能指向不可逆操作。

## UI 变更检查

1. 在中文和英文下检查溢出、空态和错误态。
2. 检查窄窗口、滚动、对话框焦点和键盘操作。
3. 确认没有重复区域、重复标题和重复监听器。
4. 对数据迁移、删除和重新计算操作检查确认与恢复路径。
5. 更新 `docs/images/` 或 README 截图时，确保画面不包含真实用户资料。
6. i18n 测试同时覆盖 HTML 静态文本和典型运行时组合文本；新增队列阶段、日志或原生对话框时必须追加对应回归用例。

## 主题

主题只修改语义颜色变量，不复制页面结构。当前提供经典、白昼、黑夜、青瓷和暮紫；新增主题必须覆盖文字、面板、字段、边框、状态色、遮罩、阴影和活跃度色阶，并验证浅色/深色原生控件的 `color-scheme`。
