## 一座资源仓库，两种整理方式

| 这次想做什么 | 你会得到什么 |
| --- | --- |
| **本地整理：先把电脑里的收藏管起来** | 原文件保持原位，为资源生成预览和清单，在仓库里分类、打标签、写备注。以后需要备份，还能把这些项目继续送去压缩。 |
| **打包备份：把资源存储到网盘或其他硬盘** | 批量压缩、完整性验证、登记仓库、记录备份位置；本地仍能看封面、视频抽帧和目录，知道每个压缩包装了什么。 |

打包和仓库登记由应用完成，网盘上传由你或同步工具完成；本地分类通过仓库标签进行管理，不会自动重排磁盘上的文件夹。

已经不压缩入库的目录可以在仓库详情中直接“校对更新”，也可以批量检查。应用在任务真正执行时只扫描一次：仅新增文件会自动合并；修改、删除或旧清单不完整时会先展示逐项变化，让你选择覆盖原项目、新建独立项目或跳过。未变化文件复用已有 MD5 和预览，不重复抽帧；整个过程不会修改、移动或删除原文件。再次拖入同一路径时，也会先引导到校对更新或压缩，而不是静默创建重复项目。

提交校对后，可到归档工作台查看进度和待确认事项。完成时会提示目录未变化或仓库已更新；需要人工处理、失败和取消也会给出对应提示。

归档工作台超过 10 个任务时使用滚动列表；从仓库切回时会重新计算可见高度，已有任务无需添加新项目即可显示。

未压缩项目已有等待或运行中的校对、压缩任务时，先完成或取消任务才能删除仓库记录。若先删除记录，再次添加同一源目录会按新项目处理。

原文件搬到新位置后，可在项目详情重新设置原文件位置；这里只更新关联，下次校对更新或压缩入库时再核对内容。未压缩项目再次压缩时，已有备份位置与本次设置冲突的，可以明确选择保留或更新。

入库自动查重，在提供相似度报告的同时，可以自动跳过已存在内容；大目录也能流畅浏览，并可快速检索整个仓库。

## 快速开始

Windows 4.8.3 正式版适用于 **Windows x64**，提供中英文界面。直接使用请选择 [Releases 发行包](https://github.com/CarlosZ16420/hamster-archiver/releases/latest)；GitHub 的 Source code 和克隆仓库用于源码开发。

1. 下载 **Setup EXE 安装版**，或完整解压 **ZIP 便携版**后运行 `HamsterArchiver.exe`。
2. 在“归档工作台”扫描目录，或拖入文件夹、视频，查看待处理内容。默认开启“小项目过滤”，阈值为 100 MB；处理较小项目时，先在“收纳设置”调整阈值或关闭过滤。
3. 想先做**本地整理**，点击“不压缩入库”；准备**打包备份**，点击“压缩入库”，再按提示选择存储位置，也可以提前填写“压缩包保存在”。完成后到“仓库”浏览和整理。

应用默认打开仓库，空仓库会提供五步首次归档引导，可选择中英文、跳过或永久关闭。扫描主目录时，一级子文件夹和视频按独立项目加入；零散图片和其他文件请先收纳到文件夹中。

启动时会先显示启动窗口，再加载归档运行模块，减少等待期间没有界面反馈的情况。

Windows 压缩和视频预览所需工具已随发行包提供，无需另装 Node.js。下载页同时提供 ZIP、Setup EXE 及各自的 `.sha256` 校验文件。

Windows 便携版完整目录为 `HamsterArchiver-v4.8.3-win-x64/`，请保留随附文件。

### Mac Beta（Apple Silicon 与 Intel）

从 [Mac Beta 预发行页](https://github.com/CarlosZ16420/hamster-archiver/releases/tag/v4.8.0-beta.mac.2) 下载 `HamsterArchiver-v4.8.0-beta.mac.2-mac-universal.dmg` 和同名 `.sha256`，核对校验值后打开 DMG，将应用拖入“应用程序”。支持 macOS 12 及以上。本 Beta 未经 Apple 公证，macOS 可能阻止首次打开；确认信任下载来源后，可在“系统设置 → 隐私与安全性”中选择“仍要打开”。Mac 资料默认保存在当前用户的应用支持目录，不随应用替换而删除。Mac 版的功能限制与构建说明见 [Mac 版指南](platforms/macos/README.md)。

Mac 目前仍为 Beta，内置 7-Zip，视频抽帧默认关闭，需要自行配置 FFmpeg；归档后支持保留或移动原文件，不提供 Windows 回收站相关删除、复原和文件撤回。更新通过下载新版 DMG 手动替换应用。

## 把整理做顺手，也把细节做好

### 文件安全：先核验，再处理原文件

压缩入库按 **生成清单 → 压缩 → 传到最终位置并验收 → 登记仓库 → 按设置处理原文件** 的顺序执行。在最终归档位置完成完整性测试，并将包内文件路径、大小和目录结构与完整源清单比对，空目录也会保留。暂存文件保留到验收通过；磁盘不足、源清单不完整、归档内容不一致或异常体积等情况会停止或要求确认，验证与登记成功后才执行原文件后处理。

<details>
<summary>展开：为文件保全和异常恢复做了哪些工作？</summary>

- 压缩前生成清单并复核源文件；跨盘移动先复制、核对完整相对路径、逐文件大小和空目录，再处理源位置。结构校对不等于逐字节内容校验。
- 归档成品在移动与清理前复核文件身份，避免误处理被同名替换的文件；分卷成品按整组处理。
- 仓库写入失败时保留已生成成品供恢复；缩略图阶段取消任务时保留源文件，并清理未提交生成物。
- 区分“源文件操作失败”和“操作已完成但状态保存失败”；大小异常成品经确认后也会保留实际移动位置等恢复线索，避免误提示重新入库。
- 追踪原文件位置与处理状态；符合条件时，可将已移动的原文件复原，Windows 还支持回收站复原。跨盘恢复按当前移后内容校对，并保留移后副本及其位置记录。
- 仓库导入只保存新增记录及其引用图片，不覆盖现有图片；导出先在目标同盘生成并验证临时 ZIP，通过后才替换旧备份。
- 数据位置失效时明确提示；切换资料位置会在正常退出后复制，并在重启时核对资料与窗口是否就绪。失败保留两边资料并安全回退。

</details>

### 便于整理：看预览，分好类，记清楚

用封面浏览收藏，用标签、星级和备注建立自己的分类习惯。标题、标签、备注、路径和文件名都能搜索；常见词匹配超过 2000 条时，结果仍可完整翻页。备份位置也可以批量记录。

列表的“大小”列显示未压缩项目的原始大小；压缩项目显示归档成品大小，便于比较所占空间。

<details>
<summary>展开：整理工具与轻快浏览的细节</summary>

- 大、中、小缩略图与文本列表满足不同浏览习惯；支持键盘翻页、输入页码、批量追加标签、修改备份位置，以及支持操作的撤回。本次运行中误删的仓库条目可撤回，相似关系一并恢复；Windows 上仍在回收站且符合恢复条件的压缩包和缩略图也可恢复。
- 标签自动补全复用已有分类，可用 Tab 接受建议；选中项目时原位更新状态，减少闪烁和页面跳动。
- 同一视频的多帧预览成组展示，竖屏画面完整保留；封面可更换，也可手动添加或粘贴补充图片。
- 大项目详情按需读取，媒体靠近可见区域才加载，同时限制图片读取数量；目录使用虚拟列表，减少无效渲染。
- 启动时后台分批加载仓库并显示进度，仓库数据完整就绪后才开放相关操作；库存、标签和活跃度入口可直接查看统计或筛选收藏。
- 列表与缩略图均支持框选、Ctrl 反选及 Shift 范围选择，可直接清空跨页选择。“仓库工具”可按偏好隐藏“未压缩”标签；向下浏览后可一键返回搜索与批量操作栏。
- 仓库保存缩略图而非再复制一整套原始媒体，预览数量可调。
- 提供五套主题与中英文界面，持续完善深色菜单、文字对比度和动态提示。

</details>

### 相似资源：给出依据，让你决定

**名称相似、文件内容一致、整个项目重复，分开显示。** 符合完整重复规则时可按设置自动跳过；只是相似的资源保留确认机会，避免因为一个公共词就替你作决定。

相似报告同时列出仓库与队列候选。队列项目注明尚未入库，并提供当前项目与候选的位置打开入口，供手动比较；仅有队列候选时不扫描目录、不补算 MD5。仓库候选保留文件级详细报告。

<details>
<summary>展开：怎样减少误报，又控制检查成本？</summary>

- 名称相似只标出实际匹配片段；点击红色词语，可确认加入排除词表，减少这类词造成的干扰。内容一致证据用金色区别显示。
- 相似判断降低短标题、数字编号和公共词的干扰；支持调整强度，手动解除的关系在后续重算时仍保持排除。
- 先用索引缩小候选，再按需核验内容；候选排除后停止多余读取，报告复用已有证据，避免逐文件遍历整个仓库。
- 同一原始位置且完整目录、文件路径、数量和大小快照都一致时，可走快捷重复判断；不满足条件时继续内容核验，不能只靠同名或同大小自动跳过。
- 跨位置项目即使文件内容相同，只要目录结构或空目录不同，就不属于完整项目重复。
- 大文件夹“卡顿规避”限制普通相似分析的代表文件数量，并可跳过极小文件的普通 MD5 记录；“MD5计算跳过极小文件”默认关闭，默认阈值为 1 KB，已有保存设置保留。完整目录清单和归档内容仍覆盖全部文件。
- 调整相似强度不会擅自启动全库重算；单项或全库重算由你选择。

</details>

### 打包方式：按你的备份习惯来

支持 7z/ZIP、密码和自定义分卷；资源多时可以批量排队、暂停或定时运行。压缩、视频抽帧和缩略图数量都可调整。

<details>
<summary>展开：压缩、密码记录与批量任务</summary>

- 压缩等级 0—9，分卷大小可设为 64 MiB—100 GiB，默认 10 GiB；仅原始总大小超过单卷大小时分卷，关闭分卷后保持整包。工具随发行包提供。
- “扫描与队列 → 设置 → 卡顿规避”中的“大文件分卷压缩，需手动确认”默认勾选；取消勾选后自动按设置分卷，并解除已有桌面任务的分卷等待，仍需手动启动队列。其他风险确认保留，不压缩入库无需分卷确认。
- 可设置压缩密码，并按项目记录解压密码；记录默认遮盖，主动显示后可查看或复制。密码记录随本地用户数据保存，应一并妥善保管。
- 队列支持 1—3 项并发、暂停、当前活动任务完成后暂停、定时运行和剩余时间估算。运行期间仍可扫描、拖放、手动添加或从仓库加入下一批任务；它们会显示在“待启动”区域，不会混入当前批次。内存不足或来源、仓库记录、输出冲突时只暂缓启动新任务。
- 勾选任务时只启动适用的所选项，无勾选时处理全部适用的待启动任务；单项失败或取消不影响其他活动任务，当前批次结束前不能清理整个队列。
- 无法启动时会说明正在运行或待人工处理的原因，并突出显示相关队列项。批次结束后可分别清理已完成（含重复跳过）或已取消任务；只移除队列项，保留仓库记录、压缩包、原文件和持久回执，仍需处理的源文件状态保存失败项不会作为已完成任务清除。
- 视频抽帧数与单项目缩略图上限可自定义，设置随任务保存。
- 密码保护不等于网盘保管承诺；软件不保证第三方平台永不审核或删除文件。

</details>

## 实验功能

### AI / Agent 协作

具备本机工具能力的 AI 可以查询收藏、添加标签，以及提交不压缩入库或压缩归档任务。临时使用时，Windows 从完整发行包根目录运行 `hamster.cmd`；Mac 版从应用内 `Contents/Resources/hamster` 运行，无需先登记宿主。

长期接入可在 **更多设置 → 实验功能 → AI 助手接入** 中按需启用，每项可以单独关闭；默认不登记宿主。Setup EXE 提供稳定的程序位置和升级/卸载生命周期，ZIP 便携版也可直接使用 CLI。

现有接入包括 Codex / ChatGPT Desktop、Codex MCP、WorkBuddy、通用 MCP，以及受支持 Windows 上的 ODR 自动发现预览。宿主支持程度由对应客户端和系统决定。

例如：“请用仓鼠症大结局把这个目录不压缩入库，保留原文件。”应用负责校验、排队和保存结果；项目粒度有实质歧义时保留必要选择，已有记录会说明本次复用、更新或跳过。

重复决策只列出有依据的可选动作；缺少可信内容匹配时会说明原因，不提供复用。明确授权复用会保留已有记录的压缩状态，复用压缩记录不等于本次新建未压缩记录。

任务回执分别记录新建、更新、复用、跳过、失败和取消，清理队列后仍可查询已保存的结果。提交后响应丢失时，可用 `task pending` 和 `task resume` 恢复同一请求；目录变化支持分页查看并明确选择覆盖、另建或跳过，异常成品和回收站安全核验继续在桌面处理。后台 AI 任务可从系统托盘或菜单栏查看，并在共享工作台标明来源。

> 这是实验功能。AI 客户端会看到工具返回的路径、标题、标签、备注等元数据；Hamster Archiver 本身不会把媒体文件上传到在线模型。具体可用性取决于所使用的 AI 客户端、操作系统和权限设置。

## 常见问题

<details>
<summary>硬盘快满了，打包后就能腾出空间吗？</summary>

打包用于组织和备份资源，不代表视频、图片一定能大幅缩小。生成成品还需要可用磁盘空间，请选择空间充足的其他硬盘作为输出位置。

需要先确认成品已在目标位置妥善保存，再决定如何处理本地文件；仍在本机保留成品或回收站文件会继续占用空间。应用的归档后处理发生在本地核验与登记完成之后，**不会等待或核实网盘上传**。计划上传后再清理的资源，请先保留原文件，自行确认备份结果。

</details>

<details>
<summary>资源和仓库数据保存在哪里？</summary>

本地整理时原文件保持原位，仓库保存索引和缩略图；打包备份的成品放在你指定的位置。Windows 便携版默认使用程序旁的 `userdata`，Windows 安装版使用 Windows 用户数据目录，卸载默认保留资料；Mac 版默认使用 `~/Library/Application Support/Hamster Archiver/`。“更多设置”提供安全切换入口。

应用自身不上传资源，网盘上传由你或同步工具完成；检查和下载更新会访问 GitHub。接入 AI 时，返回的元数据会进入所选客户端的上下文。

</details>

<details>
<summary>关闭应用后还能查看运行日志吗？</summary>

可以。运行日志保存在当前用户数据区的 `logs/app.log`，关闭应用不会清空；下次启动会在界面中恢复最近 300 条有效记录。日志包含任务处理、设置字段变化、用户数据区切换、更新操作和关键错误，但不记录密码内容，也不记录普通搜索、浏览或复制动作。

</details>

<details>
<summary>老用户如何更新？仓库导出是否包含原文件？</summary>

Windows 版可在“检查更新”中查看当前版本之后的正式发行说明并更新。联网检查只接受公开主线上的正式版，Beta 不进入自动更新候选；后台检查不会主动弹出更新窗口。便携版下载 ZIP、安装版下载 Setup EXE，两者均校验对应 SHA-256；便携更新支持失败回滚，安装版升级已有安装，新版本首次启动会显示本次变化。

网络不便时，先下载新版发行文件，再选择“手动更新”：便携版选择 ZIP，安装版选择 Setup EXE。手动选择的便携 ZIP 可以是版本号更高且校验通过的 Beta；Mac Beta 请下载新版 DMG，手动替换应用。

旧版本没有可用更新入口时，可先导出仓库，再在新程序中“并入外部仓库”；核对记录和缩略图后再处理旧目录。**仓库导出保存索引和缩略图，不等于备份原文件或归档成品**，它们仍需单独保管。

</details>
